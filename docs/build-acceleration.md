## 已调整的工作流

Build firmware 新增两个输入：`compile_jobs` 默认 `auto`，`use_cache` 默认启用。

- 自动并发按 CPU 可用核心和可用内存计算，预留约 2 GiB 给 runner，再按每个并发任务约 2 GiB 预算，最多8个任务。典型4核、16GB公开仓库 runner 会使用4个任务；也可以显式选择1/2/4/8。本地 CLI 的默认 `--jobs 2` 保留。
- 下载缓存独立保存，可跨 Profile/架构读取。正常构建系统仍验证下载文件哈希；更换锁定版本时允许回退查找旧下载，缺失或不匹配的文件仍需下载。
- C/C++ 对象缓存按宿主平台、目标/子目标、源码及 Feed 锁划分，同架构 basic/ha 可以复用。修改 LuCI JS、主题、Python 或 UCI 覆盖层不再让整组缓存失效。
- ccache 按编译器**内容**识别工具链，避免每次重建工具链导致编译器时间戳变化，从而整批缓存未命中。源码、头文件、参数等校验继续由 ccache 处理。
- 新增 Go 构建缓存。固定 Feed 原本使用 `source/tmp/go-build`；现在该路径链接到独立的 `.work/go-build`，重建源码目录后仍能保留缓存。Go 模块下载目录原本就在 `dl/go-mod-cache` 中，由下载缓存覆盖。
- Go 缓存除平台、目标和锁定版本外，还按请求配置、本地 Makefile、C/C++ 依赖及补丁隔离。Go 对外部 C 库变化的检测有限，因此 cgo 结果不会跨这些配置复用。
- 下载完成后立即保存下载缓存；即使后面的固件编译失败也能保留。C/C++ 和 Go 缓存在成功或失败的编译尝试后都会保存；不把编译失败当成成功。被取消或强制超时的任务不能保证完成缓存上传。
- 缓存服务暂时失败时允许继续正常构建。缓存键带运行编号、重试编号和 Profile，避免旧缓存不可更新以及矩阵任务互相覆盖；恢复时按兼容前缀查找最近的快照。
- 首次使用分层缓存时，若新缓存均缺失，会尝试导入该 Profile 原来的合并缓存；旧缓存若已过期则需要重新预热。
  旧下载可直接复用；编译器识别方式调整后，部分 C/C++ 对象仍需首次重新积累。

## 容量与观察方法

C/C++ 缓存上限为每次构建2 GiB；保存 Go 缓存前按使用时间裁剪到约1 GiB。下载文件另存。
GitHub 仓库默认缓存容量为10GB，旧缓存可能因容量或闲置时间被淘汰；本改动没有提高仓库付费容量。
矩阵构建会生成多个快照，频繁构建很多 Profile 时，需留意 Actions → Caches 的实际占用和淘汰情况。

每次构建的 Summary 和日志产物包含：

- 实际使用的编译并发数、缓存是否恢复成功；前缀命中也计入，不依赖仅代表“精确匹配”的 `cache-hit`。
- 下载和编译阶段的时间、退出码；失败时也记录。
- 本次 ccache 调用的命中统计（如果已构建出 ccache 工具）。
- `.work/logs/build-metrics.json`、`acceleration-plan.json`、`ccache-stats.txt` 等文件，随原来的日志产物上传。

可以用相同提交、相同 Profile 连续构建两次比较。首次缓存不齐时主要获得并发提升；第二次才适合评估完整缓存收益。若需对照冷构建，可关闭 `use_cache`。正在运行的旧任务仍使用启动时的工作流，新设置对从更新后的 `main` 新发起的任务生效。

## 为什么暂不整体缓存 build_dir / staging_dir

工具链与宿主工具确实还有进一步提速空间。但固定构建系统的 `.prepared` 等标记依赖文件时间戳；全新 Git checkout 会改变时间戳，随意恢复编译目录可能仍全部重建。
这些目录还包含绝对路径、已安装的库、目标 ABI、内核头文件及构建状态，并且通常很大。
只凭“同架构”共享它们会带来旧文件混入和依赖不一致的问题。

本轮保留每次重新检出固定源码、严格 `make defconfig` 和完整 `make`。更激进的后续方案包括：

1. 独立的工具链镜像/缓存，严格绑定宿主环境、编译器、完整配置及固定源码，并验证恢复后的时间戳和依赖行为。
2. 在专用 Linux runner 上维护各目标独立的增量工作目录；适合高频构建，但要承担维护和清理工作。
3. 仅调整 UCI 默认配置、包集合或页面时，评估 ImageBuilder / SDK；涉及内核模块、内核配置及自定义包仍需匹配构建产物。

目前没有承诺把两小时缩短到某个固定时间；实际收益由后续构建的缓存统计和阶段计时确认。

依据：[GitHub 缓存机制](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching)、[公开仓库 runner 规格](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)、[ccache 编译器识别](https://ccache.dev/manual/4.12.1.html#_configuration_options)、[Go 构建缓存](https://pkg.go.dev/cmd/go#hdr-Build_and_test_caching)。
