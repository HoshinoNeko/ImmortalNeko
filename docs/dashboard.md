# Vantage 主题、VLAN 图表与集客 AC 首页

四个构建配置（含 R619AC basic）均包含 `luci-theme-vantage`、中文资源、`luci-app-neko-dashboard` 和 `neko-observatory`。
Vantage 固定在上游 `faade36bb629f84b1e233edcad9e37abc500ae52`（1.0.20），通过单独的 feed 构建；不在启动时下载主题，也不引入 CDN。

主题在“系统 → 语言和界面”中选择 **Vantage**。保留管理员当前主题；添加主题或保留配置升级不会强制改成 Vantage。自定义“网络首页”在登录后显示，在 Bootstrap 等其他主题下也能使用。
本项目使用自己的首页模块，而不是安装上游 `luci-app-vantage`：首页的无线信息由外部 AC 提供，不再将路由器本机射频、关联终端或有线邻居当作整个无线网络。

## VLAN 速率与流量

“服务 → 首页数据采集”可设置采样间隔、历史长度、AC 地址和手动指定的逻辑接口。

- 自动识别：netifd 接口绑定 VLAN 设备，且属于未启用地址伪装的内网防火墙区域。排除 WAN 区域和 WireGuard、PPPoE、L2TPv3、VXLAN 等隧道。
- 非标准设备名称通过 UCI `device.vid` 识别。没有对应区域、使用独立设备名称，或需要统计无标签 LAN 时，可手动添加“网络 → 接口”里的逻辑接口名。
- 每个实际 L3 网络设备仅统计一次，逻辑别名不会重复累加；不叠加父桥、VLAN 子接口和交换机端口。
- 上传：VLAN 接口 RX，即终端到路由器；下载：接口 TX，即路由器到终端。包含经过该接口的内网路由流量，不能视为仅互联网流量。纯硬件交换、部分硬件卸载流量可能不经过这些计数器；本功能不会自动关闭加速。
- 速率单位为 bit/s；累计量为字节。累计量是**采集器启动后有效采样的增量总和**，不是账单、月度流量或设备生命周期计数。
- 图表按真实时间绘制，可切换 VLAN 和 5 / 30 / 60 分钟范围，并悬停查看数值。默认每 5 秒采样、360 点，保留约 30 分钟；若要覆盖 60 分钟，可设置 720 点。
- 设备重建、计数回退、采样中断超过 30 秒会重新建立基线，保留图表缺口，不制造速率尖峰。最多 32 个设备、每设备 720 点；历史与累计量仅存于 RAM，采集器或设备重启后清除，不持续写闪存。

## 集客 AC

默认地址为用户指定的 `http://172.16.10.89`。凭据尚未在设备本地配置时，首页显示缺少凭据，不能显示为“零终端”。宿舍设备可在设置中关闭 AC 采集，或通过已有的 VPN 路由访问家中 AC；此功能不会修改 VPN、路由或防火墙。

在设备本地创建 `/etc/neko-observatory/ac-password`，只保存 AC 登录密码本身（可带一个末尾换行），所有者 root、权限 `600`，目录权限 `700`。请使用本地编辑器填写，避免把密码写进 shell 命令历史或公开配置。

```sh
install -d -m 700 /etc/neko-observatory
touch /etc/neko-observatory/ac-password
chmod 600 /etc/neko-observatory/ac-password
vi /etc/neko-observatory/ac-password
/etc/init.d/neko-observatory enable
/etc/init.d/neko-observatory restart
```

默认凭据目录列入 sysupgrade 保留清单，**备份也会含有此目录，应私密保存**。若使用其他文件路径，请自行加入 `/etc/sysupgrade.conf`。固件和仓库不包含实际密码、令牌或现场终端清单。

采集协议复用先前验证的 GECOOS API：

1. `GET /api/getrandom` 获取随机数。
2. `POST /api/sysauth`，提交 `md5(random + 登录密码)` 获取会话。
3. 带 `sysauth` 请求头，仅 GET `ac/apsearch`、`ac/stasearch`、`ac/hotspotsearch`，自动获取分页。

仅登录使用 POST；不调用配置、重启、踢终端等接口。不跟随重定向、不使用环境代理，HTTPS 使用证书验证。认证过期最多重新登录一次，每次采集设有时间与页数上限；只有三个查询全部成功后才发布新快照。凭据轮换在下次采集时生效。

AP 查询可能同时返回无线密钥后缀等字段，因此采用字段白名单，绝不把原始响应直接转发给浏览器。公开给登录用户的内容仅包括：

- AP 名称、型号、IP、在线标记、终端数、最后上报时间；旧上报单独标记。
- 实际热点中的 SSID、VLAN、所属 AP 和频段，按 SSID/VLAN 组合展示，不用 AC 全局模板数量代替广播网络数量。
- 终端名称、IP、MAC、SSID、VLAN、AP、频段和信号。未核实量纲的 AC 链路速率不作为实际吞吐量展示。
- 按 MAC 去重的唯一终端数和原始关联记录数分别显示，漫游重复关联明确提示；暂缺 IP 不等于离线。

默认每 30 秒查询 AC。失败时保留最后成功数据和时间，明确显示错误；超过 120 秒标为过期。AP 上报默认超过 180 秒单独标为过期。AC 自报在线不等于采集器独立验证 AP 存活。

## 权限与验证范围

浏览器只调用 `neko.observatory.status` 读取过滤后的内存快照。只读首页 ACL 没有文件访问、命令执行、UCI 写入或 AC 凭据访问权限。采集设置使用独立 ACL，仅允许访问 `neko-observatory` 配置。新增了这些 ACL；未扩展全局文件或命令权限。

已对实际 AC 做新一轮登录和三个只读分页查询；私有响应不进入测试夹具或仓库。测试覆盖认证、会话复用、过期重试、分页异常、字段过滤、终端去重、文件权限、VLAN 去重、计数器重置、断采与历史边界。四种 profile 通过实际固定源码 `make defconfig` 严格依赖检查。完整固件编译及真实 LuCI 页面安装需要对应构建/部署；这些检查不代表已刷入设备。
